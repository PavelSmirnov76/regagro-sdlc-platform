# MOD-6 — PROFILE

Профиль пользователя и настройки приложения: редактирование профиля, язык
интерфейса, уведомления о вакцинации, видимость видов животных, настройки
подключаемых сканирующих устройств. Физически размазан по четырём
независимым папкам кода, связанным только навигацией; ни один маршрут этого
раздела не имеет route-guard по авторизации.

## Назначение

Всё, что пользователь настраивает про себя и про приложение, а не про
конкретное животное/ферму/объявление.

## Граница — что модуль explicitly не владеет

- Сама учётная запись (`User` — id/аутентификация/логаут/удаление аккаунта) —
  модуль `AUTH`, уже специфицирован ([ACTOR-1](../actors/ACTOR-1-USER-IN-AUTH.md),
  `EVT-7`/`EVT-9`); кнопки логаута/удаления аккаунта физически на экране
  `ProfileSettingsPage`, но их логика не переопределяется здесь.
- Таксономия видов/пород/мастей (`Kind`/`Breed`/`Suit`) в целом — модуль
  `HANDBOOKS`; этот модуль владеет только узкой гранью — колонкой
  `Kind.visible`.
- `Kind.visible` дополнительно редактируется независимым, отдельно
  написанным путём при онбординге первой фермы (`FarmCreateCubit`, шаг
  `FarmCreateStep.kindsVisibility`, модуль `FARM`, уже специфицирован) — тот
  же факт, два не связанных друг с другом кода; это отмечено как находка
  внутри use-case этого модуля, не переспецифицируется в `FARM`.
- Применение настроек сканера к реальному оборудованию во время сканирования
  (`ScannerService`) — используется модулями `ANIMAL` (REG/WEIGH/INV), не
  специфицируется здесь; этот модуль владеет только хранением/редактированием
  настроек.
- Явный полный sync pass как таковой — модуль `SYSTEM` (последний в очереди),
  не здесь; push/pull именно настроек сканера специфицируются здесь как
  часть R66, т.к. это единственный факт синхронизации, принадлежащий
  исключительно этому модулю (в отличие от справочников).
