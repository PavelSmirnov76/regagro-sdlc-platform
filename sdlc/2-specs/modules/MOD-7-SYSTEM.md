# MOD-7 — SYSTEM

Последний модуль в очереди пересборки `sdlc/`. Явный полный sync pipeline
(оркестрация верхнего уровня — каждая отдельная сущность уже
специфицирована в `FARM`/`ANIMAL`/`PROFILE`), сводный экран «В работе»,
контейнер календаря событий, проверка обновления приложения, синхронизация
справочников `HANDBOOKS`/`BOARD` (сам факт синка, отложенный этими
модулями до сюда).

## Назначение

Всё кросс-модульное — то, что не принадлежит ни одной отдельной сущности,
а координирует/агрегирует множество уже специфицированных сущностей, плюс
факты, для которых предыдущие модули явно оставили место здесь.

## Состав

- Акторы: [ACTOR-1](../actors/ACTOR-1-USER-IN-AUTH.md) (переиспользован —
  ручной запуск синка, просмотр «В работе»/календаря), [ACTOR-3](../actors/ACTOR-3-APP-IN-AUTH.md)
  (переиспользован — автозапуск синка при старте, проверка обновления),
  [ACTOR-4](../actors/ACTOR-4-SYSTEM-IN-SYSTEM.md) (переиспользован —
  синхронизация справочников).
- Сущности: [ENT-23](../entities/ENT-23-DATA-UPDATE-IN-SYSTEM.md) (DataUpdate —
  журнал sync-прохода), [ENT-24](../entities/ENT-24-NEW-APP-VERSION-IN-SYSTEM.md)
  (NewAppVersion).
- События: [EVT-93](../events/EVT-93-FULL-SYNC-PASS-TRIGGERED-AUTOMATICALLY-IN-SYSTEM.md)…[EVT-101](../events/EVT-101-DAY-EVENTS-LIST-VIEWED-IN-SYSTEM.md)
  (`events/EVT-*-IN-SYSTEM.md`).
- Use-cases: `use-cases/UC-*-IN-SYSTEM.md` — см. индекс [use-cases/README.md](../use-cases/README.md).

## Граница — что модуль explicitly не владеет

- Push/pull каждой отдельной сущности (Farm/Place — `FARM`;
  Movement/Vaccination/AnimalWeighing/Disposal/InventoryScanReport —
  `ANIMAL`; настройки сканера — `PROFILE`) — уже специфицированы в своих
  модулях, этот модуль владеет только верхнеуровневой оркестрацией
  (`DataUpdateBloc.on<DataUpdateStartAll>` как целое, не отдельные
  `_syncFarms`/`_syncPlaces`/и т.д.).
- Посуточное СОДЕРЖИМОЕ дня по каждому типу (взвешивание/вакцинация/
  перемещение/выбытие/инвентаризация конкретного дня, детальный отчёт) —
  уже специфицировано по типам в `ANIMAL`; этот модуль владеет только
  контейнерами верхнего уровня — месячным календарём
  ([EVT-99](../events/EVT-99-EVENTS-CALENDAR-VIEWED-IN-SYSTEM.md)) и
  промежуточным посуточным списком-агрегатором между календарём и
  отчётом по типу ([EVT-101](../events/EVT-101-DAY-EVENTS-LIST-VIEWED-IN-SYSTEM.md),
  `ReportsDayListCubit`/`FarmDayListCubit` — обнаружен при
  специфицировании календаря, ранее не был описан ни в одном модуле).
  Регистрация — исключение: её посуточный экран (`RegistrationDayReportPage`)
  чистый passthrough без собственной логики, описан как деталь
  [EVT-101](../events/EVT-101-DAY-EVENTS-LIST-VIEWED-IN-SYSTEM.md), не
  как отдельное событие ANIMAL/REG.
- Сами сущности справочников (`Kind`/`Breed`/`Suit`/`Country`/`DisposalReason`
  и т.д., `ENT-3`…`ENT-8`) — `HANDBOOKS`, уже специфицирован; этот модуль
  специфицирует только факт их периодической инкрементальной
  синхронизации, отложенный `HANDBOOKS` сюда.
- Справочники объявлений (типы/статусы/атрибуты/типы услуг) как сущности —
  `BOARD` ([ENT-18](../entities/ENT-18-AD-IN-BOARD.md), поля); этот модуль
  специфицирует только факт их синхронизации как часть общего
  directories-прохода.
- Логаут как таковой (`EVT-7`, `ACTOR-1`) и автоматическая потеря сессии
  (`EVT-8`, `ACTOR-3`) — уже специфицированы в `AUTH`; этот модуль
  специфицирует только последующую очистку локальных данных
  (`DataUpdateClear`), которую они запускают.
- Навигационная оболочка (`main/`, `main_navigator/`) как таковая — чистая
  инфраструктура, не специфицируется отдельно, за исключением фактов,
  прямо описанных в событиях этого модуля (автозапуск синка при старте,
  сброс навигации после смены языка — последнее уже частично описано в
  `PROFILE`, `EVT-83`).

Это последний модуль пересборки — после него `sdlc/2-specs/` специфицирован
целиком по всем модулям (AUTH, HANDBOOKS, FARM, ANIMAL, BOARD, PROFILE,
SYSTEM).
