# ENT-13 — Movement

## Описание

Запись о перемещении одного животного между местами — Drift-таблица `Movements`. Одна запись на одно животное (групповое перемещение нескольких животных создаёт по одной строке на каждое, не одну групповую запись).

## Поля

| Поле | Тип | Комментарий |
|---|---|---|
| `id` | int, autoincrement | локальный id |
| `remoteId` | int? | серверный id — заполняется только для записей, загруженных с сервера |
| `animalId` | int | ссылка на [ENT-11](ENT-11-ANIMAL-IN-ANIMAL.md) |
| `placeId` | int | целевое место (`idRemote` выбранного места назначения) |
| `fromId` | int? | место отправления (`idRemote`); `null` для животных «без места» |
| `placeDate` | DateTime | |
| `sync` | bool, default false | признак отправки на сервер |
| `guid` | text | генерируется на клиенте при создании |
| `userId` | int? | пользователь, создавший запись, `-1` при отсутствии |

## Связи

- [ENT-11](ENT-11-ANIMAL-IN-ANIMAL.md) (Animal) — многие-к-одному по `animalId`; перемещение немедленно обновляет `Animal.placeId` локально, до подтверждения сервера.

## Инварианты

- **Создание местно-first, немедленное.** `Animal.placeId` обновляется в момент локального сохранения записи, не после синхронизации — без проверки сети перед сохранением.
- **Список выбранных животных перед сохранением повторно выбирается из БД с фильтром «не удалено»** — животные, помеченные как удалённые/выбывшие между выбором в UI и нажатием кнопки, автоматически исключаются из создаваемых записей.
- **Push — единый батч-запрос на все ещё не отправленные записи разом**, не по одной. Успех (`sync=true`) применяется ко всем записям батча одновременно — партиального успеха на уровне отдельной строки нет; отказ или исключение пробрасывается наружу и прерывает весь sync-проход.
- **Pull перезаписывает локальную таблицу целиком**, но только если сервер вернул непустой список; пустой ответ не трогает локальные данные. Ошибка pull только логируется, не прерывает остальной sync-pipeline — в отличие от push.
- **Удаление одной ещё не отправленной записи откатывает `Animal.placeId` на `fromId`, но только если текущее место животного всё ещё равно `placeId` этой записи** — если животное с тех пор переместили чем-то другим, откат не выполняется. Откат также не выполняется, если у записи отсутствует `animalId`, `fromId` или `placeId`.
- **Массовое удаление записей при удалении самого животного не откатывает `Animal.placeId`** — использует общий `deleteAll`, минуя переопределённый `delete()` с откатом.
- **При замене локального id животного на серверный все связанные записи `Movement` каскадно обновляются** на новый `animalId`.
- **В истории животного (read-only таймлайн) показываются только уже синхронизированные записи** (`sync: true` по умолчанию) — неотправленные перемещения там не отображаются.
