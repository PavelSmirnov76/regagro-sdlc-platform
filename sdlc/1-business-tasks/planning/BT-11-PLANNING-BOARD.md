# BT-11 — Специфицировать модуль BOARD (доска объявлений + чат)

## Текущее состояние

Доска объявлений (продажа животных/услуги) + приватный чат с автором
объявления — первый модуль за пределами только что закрытого
`MOD-4-ANIMAL`. Полностью online-only: ни объявления, ни чаты/сообщения не
кэшируются локально (Drift хранит только справочники — типы/статусы/
атрибуты объявлений, типы услуг — используемые исключительно этим модулем).
Доступность раздела зависит от страны пользователя (`Country.boardEnabled`,
читается из уже специфицированного `HANDBOOKS`) — реактивный UI-гейт, не
route-guard. Лента/карточка объявления доступны и гостю, и авторизованному
пользователю одинаково; публикация/редактирование/удаление объявления,
избранное, чат — только авторизованному.

## Что делать

Специфицировать модуль [MOD-5](../../2-specs/modules/MOD-5-BOARD.md) с нуля
(первый модуль за пределами `MOD-4-ANIMAL`) — написать глоссарий (сущности:
объявление, чат, сообщение чата) и use-case на каждый достижимый сценарий по
`R50`–`R61`, **включая read-экраны** (лента, «Мои объявления», «Избранное»,
список чатов, переписка) — read-экраны не откладываются, специфицируются в
этом же проходе.

Акторы — переиспользовать существующие, не заводить новых:
- [ACTOR-1](../../2-specs/actors/ACTOR-1-USER-IN-AUTH.md) (авторизованный
  пользователь) — для мутаций (публикация/правка/удаление объявления,
  избранное, чат/сообщения, «Мои объявления»/«Избранное» как списки) — этот
  актор уже explicitly анонсировал BOARD как будущего потребителя в своём
  файле.
- [ACTOR-5](../../2-specs/actors/ACTOR-5-USER-IN-ANIMAL.md) (текущий
  пользователь, гость=авторизованный одинаково) — для чисто читающих
  сценариев, доступных и гостю: лента, карточка объявления, звонок по
  телефону из карточки. Второй модуль, где этот актор используется (после
  ANIMAL) — в пределах допустимого без переноса суффикса
  (`../../2-specs/actors/AGENTS.md`, «for an actor used by one or two
  modules beyond its home»).
- [ACTOR-3](../../2-specs/actors/ACTOR-3-APP-IN-AUTH.md) (приложение,
  автоматические проверки) — для реактивной проверки доступности раздела по
  стране (`BoardChatAvailabilityCubit`).

Границы: справочники объявлений (типы/статусы/атрибуты/типы услуг) —
описать как поля/связи внутри сущности объявления, не как отдельные
сущности (используются только этим модулем, тот же паттерн, что у VAC/DISP
в ANIMAL). `Country.boardEnabled` — читается, но не редактируется этим
модулем; сама сущность `Country` (`ENT-4`, HANDBOOKS) уже специфицирована и
не редактируется здесь — читается по ссылке.

## Критерии приёмки

- [ ] Сущности объявления/чата/сообщения написаны.
- [ ] События публикации/правки/удаления/избранного объявления, отправки
      сообщения (включая автосоздание чата первым сообщением), read-экранов
      (лента/мои/избранное/список чатов/переписка), проверки доступности по
      стране и звонка по телефону написаны.
- [ ] Use-case на каждый достижимый сценарий (успех/ошибка) написан.
- [ ] Каждый use-case со связанным тестом или явным «TBD — теста нет».
