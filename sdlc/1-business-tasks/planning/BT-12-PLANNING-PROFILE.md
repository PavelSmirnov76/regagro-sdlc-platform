# BT-12 — Специфицировать модуль PROFILE

## Текущее состояние

Профиль пользователя и настройки приложения — физически размазаны по
четырём независимым папкам (`lib/pages/profile/`, `lib/pages/profile_settings/`,
`lib/pages/language/`, `lib/pages/scanner_settings/`), связанным только
навигацией. Ни один маршрут этого раздела не имеет route-guard по
авторизации — весь раздел технически доступен и гостю (гостевой путь
сохранения профиля не шлёт ничего на сервер, только локальные
предпочтения — страну/язык). Пять независимых под-фич: редактирование
профиля (R62), язык интерфейса (R63, физически завязан на тот же экран и
Cubit, что и R62, но отдельный эффект), уведомления о вакцинации (R64),
видимость видов животных (R65, узкая грань справочника `Kind`, которым в
целом владеет HANDBOOKS), настройки сканирующих устройств (R66).

## Что делать

Специфицировать модуль [MOD-6](../../2-specs/modules/MOD-6-PROFILE.md) —
глоссарий (сущности: настройки уведомлений, устройство сканера — профиль
пользователя переиспользует уже специфицированный [ENT-1](../../2-specs/entities/ENT-1-USER-IN-AUTH.md)
из AUTH, видимость видов переиспользует таксономию
[ENT-3](../../2-specs/entities/ENT-3-TAXONOMY-IN-HANDBOOKS.md) из HANDBOOKS —
ни того, ни другого не редактировать, читать по ссылке) и use-case на каждый
достижимый сценарий по `R62`–`R66`, **включая read-экраны** — не
откладываются, специфицируются в этом же проходе.

Акторы — переиспользовать существующие:
- [ACTOR-5](../../2-specs/actors/ACTOR-5-USER-IN-ANIMAL.md) (гость=авторизован
  одинаково) — для всех пользовательских сценариев этого модуля, весь раздел
  без route-guard по авторизации.
- [ACTOR-4](../../2-specs/actors/ACTOR-4-SYSTEM-IN-SYSTEM.md) (система/sync) —
  для push/pull настроек сканера на сервер.

## Критерии приёмки

      осознанный отказ бизнес-правилом) написан.
- [ ] Каждый use-case со связанным тестом или явным «TBD — теста нет».
