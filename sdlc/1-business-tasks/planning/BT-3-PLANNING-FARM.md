# BT-3 — Специфицировать модуль FARM

## Текущее состояние

Справочник ферм (юридических площадок СХТП) и отделений (мест содержания животных внутри фермы) — создание/редактирование локально, с явной синхронизацией на сервер отдельным шагом. Удаление отделения — тоже живая функциональность (при условии отсутствия закреплённых животных); удаления фермы как пользовательской функциональности в коде нет вообще (мёртвый код вычищен в этом же проходе, см. `SDLC-REWRITE-PLAN.md`, «Статус — чистка кода»).

## Что делать

Написать глоссарий модуля (`MOD`/`ACTOR`/`ENT`/`EVT`) и use-case спеки на каждый достижимый из кода сценарий по `R1`–`R11`, по конвенции `sdlc/2-specs/`. Здесь впервые в этом проходе понадобится системный (sync-проходной) актор — заводится как `-IN-FARM` (первый модуль, которому понадобился), с осознанием, что при специфицировании `SYSTEM` (последний модуль в очереди) его суффикс, вероятно, будет перенесён на `-IN-SYSTEM` — тем же порядком, каким в прошлой версии дерева был перенесён суффикс актора обычного пользователя на AUTH (см. `sdlc/2-specs/actors/AGENTS.md`, «Refinement for actors used broadly»). Это не ошибка, а штатная, заранее осознанная часть процесса — записано в `SDLC-REWRITE-PLAN.md`.

## Критерии приёмки

- [ ] `MOD-3-FARM.md` написан, с границей модуля.
- [ ] Акторы (переиспользуемый обычный пользователь + новый системный/sync), сущности, события FARM написаны.
- [ ] Use-case на каждый достижимый сценарий (успех/ошибка/бизнес-отказ) по `R1`–`R11` написан, включая живое удаление места и отсутствие удаления фермы.
- [ ] Каждый use-case со связанным тестом или явным «TBD — теста нет».
