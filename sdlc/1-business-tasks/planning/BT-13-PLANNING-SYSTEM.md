# BT-13 — Специфицировать модуль SYSTEM (последний в очереди)

## Текущее состояние

Системное/кросс-модульное: явный полный sync pipeline (`DataUpdateBloc`),
сводный экран «В работе», контейнер календаря событий (месячный вид с
индикаторами — посуточное содержимое по каждому типу уже специфицировано в
`ANIMAL`), проверка обновления приложения, синхронизация справочников
`HANDBOOKS`/`BOARD` как часть общего directories-прохода (сам факт
синхронизации намеренно отложен `HANDBOOKS`/`BOARD` до этого модуля — см. их
границы). Push/pull КАЖДОЙ отдельной сущности (Farm/Place/Movement/
Vaccination/AnimalWeighing/Disposal/InventoryScanReport/Device) уже
специфицированы отдельно в `FARM`/`ANIMAL`/`PROFILE` — этот модуль
специфицирует только верхнеуровневую оркестрацию, которая их запускает, и
факты, для которых ни один предыдущий модуль не был подходящим владельцем.

## Что делать

Специфицировать модуль [MOD-7](../../2-specs/modules/MOD-7-SYSTEM.md) —
глоссарий (сущности: журнал sync-прохода, версия приложения) и use-case на
каждый достижимый сценарий по `R67`–`R72`, **включая read-экраны** («В
работе», календарь) — не откладываются, специфицируются в этом же проходе.

Акторы — переиспользовать существующие, не заводить новых:
- [ACTOR-1](../../2-specs/actors/ACTOR-1-USER-IN-AUTH.md) (авторизованный) —
  ручной запуск sync-прохода, просмотр «В работе»/календаря.
- [ACTOR-3](../../2-specs/actors/ACTOR-3-APP-IN-AUTH.md) (приложение,
  автоматические действия) — автозапуск sync-прохода при старте, проверка
  обновления приложения после успешного прохода.
- [ACTOR-4](../../2-specs/actors/ACTOR-4-SYSTEM-IN-SYSTEM.md) (система,
  sync-проход) — синхронизация справочников как часть прохода.

Это последний модуль в очереди пересборки `sdlc/` — после него весь
`2-specs/` специфицирован по актуальному коду с нуля.

## Критерии приёмки

- [ ] Сущности журнала sync-прохода и версии приложения написаны.
- [ ] События автоматического/ручного запуска полного sync-прохода, очистки
      локальных данных при логауте, синхронизации справочников (ANIMAL/
      HANDBOOKS и BOARD раздельно), read-экранов («В работе», календарь) и
      проверки обновления приложения написаны.
- [ ] Use-case на каждый достижимый сценарий (успех/ошибка) написан.
- [ ] Каждый use-case со связанным тестом или явным «TBD — теста нет».
