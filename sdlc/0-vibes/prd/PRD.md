## Purpose & scope

Продукт — мобильное приложение «Электронный паспорт» (направление «Овцеводство»): регистрация сельскохозяйственных животных, проведение ветеринарных мероприятий (вакцинация, взвешивание, перемещение, выбытие, разведение/родословная, инвентаризация через RFID), доска объявлений с чатом между пользователями, и offline-first синхронизация с бэкендом.

Это не пилот и не MVP — продукт опубликован и распространяется через App Store и Google Play, с широкой уже построенной функциональной поверхностью.

Границы: мобильное приложение (Flutter UI, локальная Drift/SQLite БД, Hive auth-хранилище, scanner/BLE-сервисы, in-app sync pipeline). Внешний бэкенд RINT (единый API-гейтвей: авторизация, справочники, фермы/места/животные, объявления/чат) — за границей, зависимость и источник данных, не часть того, что этот PRD специфицирует изнутри.

Работа приложения — offline-first: основной сценарий работает без сети, синхронизация с сервером — отдельный явный шаг.

## Goals and non-goals

### Non-goals (явные исключения из текущего фокуса)

- Понятие ЛПХ (личное подсобное хозяйство) как отдельная сущность — в модели продукта отсутствует.

## Requirements

Пронумерованы по функциональным областям продукта. Каждое требование реализуется одним или несколькими use-cases в `2-specs/use-cases/` — сам PRD этого обратного списка не ведёт.

**FARM — Фермы и места**
- **R1** — Создание фермы с указанием названия и физического адреса.
- **R2** — Редактирование названия и адреса фермы.
- **R3** — Просмотр карточки фермы со сводной статистикой — список отделений и количество животных.
- **R4** — Переключение между несколькими фермами пользователя.
- **R5** — Офлайн-создание и офлайн-редактирование фермы с последующей синхронизацией на сервер и заменой локального id на серверный.
- **R6** — Автоматическое предложение стандартного набора отделений при первой настройке структуры новой фермы.
- **R7** — Добавление собственных отделений (мест) фермы с указанием названия и площади.
- **R8** — Редактирование названия и площади отделения.
- **R9** — Удаление отделения при условии, что в нём нет закреплённых животных.
- **R10** — Просмотр карточки отдельного отделения со списком закреплённых за ним животных.
- **R11** — Офлайн-создание, офлайн-редактирование и офлайн-удаление отделений с синхронизацией на сервер, включая удаление на сервере.

**AUTH — Авторизация**
- **R12** — Саморегистрация владельца-аккаунта.
- **R13** — Вход в систему по логину/паролю и выход из аккаунта (logout) как его симметричная операция.
- **R14** — Запоминание последнего использованного логина и его автоподстановка при следующем запуске приложения.
- **R15** — Автоматический вход в систему сразу после успешной саморегистрации или после сброса пароля, без повторного ввода данных пользователем.
- **R16** — Восстановление пароля.
- **R17** — Гостевой доступ до входа/регистрации.
- **R18** — Удаление аккаунта пользователя.

**REG — Регистрация животного**
- **R19** — Регистрация нового животного как local-first процесс (без немедленной отправки на сервер), одинаково доступный гостю и авторизованному пользователю.
- **R20** — Пошаговый визард регистрации животного с выбором вида, породы, масти, пола, даты рождения и места содержания.
- **R21** — Указание идентификационных маркеров животного (например, номера транспондера и бирки) при регистрации, включая проверку на дублирование уже занятых номеров.
- **R22** — Быстрая последовательная регистрация нескольких животных подряд («сохранить и добавить ещё») с переносом общих для группы данных.
- **R23** — Редактирование данных уже зарегистрированного животного (порода, масть, дата рождения, пол).
- **R24** — Офлайн-регистрация и офлайн-редактирование животного с синхронизацией на сервер и заменой локального id на серверный.

**MOVE — Перемещение**
- **R25** — Перемещение одного или нескольких животных между местами содержания в рамках фермы, с немедленным локальным обновлением текущего места животного.
- **R26** — Просмотр списка ещё не отправленных на сервер перемещений и их отмена (удаление) с восстановлением прежнего места животного.
- **R27** — Офлайн-создание перемещений с последующей отправкой на сервер при синхронизации.

**VAC — Вакцинация**
- **R28** — Запись, редактирование и удаление вакцинации животного; редактирование и удаление уже отправленной на сервер записи — отложенное, через sync-очередь, не немедленное.
- **R29** — Вычисляемый статус вакцинации (актуальна/скоро/просрочена/отсутствует/завершена) без хранения в БД.

**WEIGH — Взвешивание**
- **R30** — Фиксация веса животного вручную либо автоматически через подключаемые по Bluetooth весы, с указанием даты и статуса здоровья.
- **R31** — Последовательное взвешивание нескольких животных в рамках одной сессии без выхода с экрана.
- **R32** — Редактирование и удаление ранее сохранённой записи взвешивания.
- **R33** — Автоматический расчёт среднесуточного привеса (ADG) между двумя последовательными взвешиваниями животного.
- **R34** — Офлайн-фиксация взвешивания с последующей синхронизацией на сервер.

**DISP — Выбытие**
- **R35** — Оформление выбытия одного или нескольких животных с указанием причины из справочника причин выбытия.
- **R36** — Оформление перемещения животных между фермами одного владельца как отдельного сценария выбытия, с выбором целевой фермы и целевого места.
- **R37** — Просмотр списка ещё не отправленных на сервер записей о выбытии и их отмена (удаление).
- **R38** — Офлайн-оформление выбытия с последующей отправкой на сервер при синхронизации.

**REPRO — Разведение/родословная**
- **R39** — Привязка родителей (матери и отца) к животному — по ссылке на существующую зарегистрированную запись либо вводом текстового номера без привязки к записи («не зарегистрировано»).
- **R40** — Привязка потомка животному — операция, симметричная привязке родителя.
- **R41** — Экран «Разведение» карточки животного с раздельными вкладками «Родители» и «Потомство», где список потомства вычисляется автоматически по всем животным, ссылающимся на текущее как на родителя.
- **R42** — Поиск кандидата в родители или потомки по номеру идентификации — сканированием либо вручную, с ограничением по виду животного и правдоподобием даты рождения относительно текущего животного.
- **R43** — Изменение родителя/потомка у уже синхронизированного животного передаётся на сервер отложенно, через общий цикл синхронизации правок животного.

**INV — Инвентаризация/проход**
- **R44** — Проведение инвентаризации поголовья места содержания через сканирование RFID/UHF-меток подключаемым сканером или сканирующим терминалом.
- **R45** — Сохранение черновика сессии инвентаризации локально по ходу сканирования и его продолжение (доскан) позже, а не только завершение сразу.
- **R46** — Список ещё не отправленных сессий инвентаризации с возможностью открыть любую из них для продолжения.
- **R47** — Отчёт по итогам инвентаризации — какие животные учтены, какие не найдены среди сканов, какие отсканированные номера не относятся ни к одному животному места.
- **R48** — Экспорт отчёта об инвентаризации в Excel/PDF.
- **R49** — Офлайн-проведение инвентаризации с последующей отправкой результатов на сервер при синхронизации.

**BOARD — Объявления**
- **R50** — Публикация объявления о продаже животного (одного или нескольких) либо объявления об услуге — с заголовком, описанием, фотографиями, адресом и контактным телефоном.
- **R51** — Редактирование собственного объявления.
- **R52** — Удаление собственного объявления.
- **R53** — Просмотр ленты объявлений с постраничной подгрузкой, поиском по названию и фильтрацией по виду/породе/масти/типу объявления.
- **R54** — Просмотр списка «Мои объявления» — объявлений текущего пользователя.
- **R55** — Добавление и удаление объявления из избранного, отдельный экран просмотра избранных объявлений.
- **R56** — Просмотр детальной карточки объявления.
- **R57** — Доступность раздела объявлений и чата в приложении зависит от того, включён ли этот функционал для страны пользователя.
- **R58** — Чат с автором объявления, создаваемый автоматически при первом отправленном сообщении.
- **R59** — Список чатов пользователя с превью последнего сообщения и счётчиком непрочитанных.
- **R60** — Отправка и получение текстовых сообщений в чате.
- **R61** — Звонок по номеру телефона, указанному в объявлении, прямо из карточки объявления или переписки.

**PROFILE — Профиль/настройки**
- **R62** — Просмотр и редактирование профиля пользователя (имя, email, телефон, страна).
- **R63** — Смена языка интерфейса приложения из списка поддерживаемых языков.
- **R64** — Настройка уведомлений о вакцинации — за сколько дней до неё предупреждать и включена ли отправка на email.
- **R65** — Настройка видимости видов животных, отображаемых в приложении.
- **R66** — Настройка параметров подключаемых сканирующих устройств (терминал, Bluetooth- и UHF/RFID-сканеры).

**Сквозные**
- **R67** — Явный, запускаемый пользователем полный sync pipeline, объединяющий отправку локальных изменений и получение актуальных данных по всем сущностям приложения.
- **R68** — Сводный экран «В работе», показывающий количество ещё не отправленных на сервер записей по каждому типу операций со ссылками на соответствующие списки.
- **R69** — Календарь и посуточный список событий фермы/места, объединяющий регистрацию, вакцинацию, взвешивание, перемещение, выбытие и инвентаризацию за выбранный день.
- **R70** — Проверка наличия новой версии приложения при запуске, с принудительным обновлением, если новая версия помечена обязательной.

**HANDBOOKS — Справочники**
- **R71** — Справочные данные, используемые несколькими модулями приложения (виды/породы/масти животных, страны, причины выбытия, вакцины, единицы измерения и т.д.), синхронизируются с сервером и остаются доступны офлайн.
- **R72** — Синхронизация справочников инкрементальна — при повторных проходах загружаются только изменения с момента последней успешной синхронизации, без полной перезагрузки.

## Success metrics

Исходное продуктовое видение, перенесённое без пересмотра (PRD не переопределяет бизнес-метрики):

- Количество регистраций животных.
- Количество проведённых ветеринарных мероприятий и событий.
- Количество обращений в техподдержку.
- Количество пользователей.
- Количество сбоев — код-верифицированные дефекты, инвентаризированные по модулям в `sdlc/2-specs/modules/`.

Инструментальная аналитика не подключена — единственные текущие каналы сигнала: обращения в техподдержку и ручное тестирование. Целевые числовые значения ни для одной метрики не заданы — вне охвата специфицируемого домена (специфицируется поведение кода, не бизнес-цели). Ближайшая задача после завершения пересборки `sdlc/` — подключение инструментов аналитики.

## Technical requirements

- Flutter/Dart, iOS/Android; pub workspace (корневой пакет + `packages/sheep_farm_database`, локальная БД на Drift/SQLite).
- Авторизационные данные — отдельное Hive-хранилище.
- Сеть — Dio + кастомный RPC-клиент (`ApiMessage` freezed DTO).
- DI — `get_it`; навигация — `go_router`.
- Кодогенерация — `freezed`/`json_serializable`/`drift`/`hive` через `build_runner --workspace`.
- Аппаратные интеграции — BLE (весы), RFID/UHF-сканер.
- Билд-флейворы: `dev`, `prod` — единый бэкенд RINT, единый `applicationId`/bundle id (`com.regagro.passport`).

## Dependencies

Внешний бэкенд — зависимость, не пользователь: RINT (единый API-гейтвей — auth: вход/токены/профиль; справочники; фермы/места/животные; объявления/чат).

## Constraints

Архитектурные ограничения, обнаруженные в коде (не результат единого проектного решения):

- Нет единой сущности синхронизации/outbox — у каждой сущности свой bespoke success/error паттерн синка.
- Перемещение животного меняет `Animal.placeId` локально до подтверждения сервера; автоматический откат существует только при локальном удалении записи о перемещении (и только если с тех пор не было более нового перемещения) — при отказе самой синхронизации отдельного отката нет.
- Выбытие не помечает животное как выбывшее локально — статус приходит только из серверного ответа при следующей загрузке.
- Статус вакцинации — вычисляемое поле (не хранится в БД), считается из дат и покрытия болезней при каждом чтении.
- Замена локального id на серверный после успешной синхронизации животного обязана обновить все связанные локальные записи (взвешивания, вакцинации, перемещения, идентификации, невыгруженное выбытие) — распределённая по нескольким репозиториям операция, не одна транзакция с гарантией на уровне БД.
- Синхронизация инвентаризационных скан-отчётов не проверяет содержимое ответа сервера на логический отказ (только сетевое исключение прерывает синк раньше) — при осознанном отказе сервера (HTTP 200 с телом-ошибкой) локальные неотправленные записи всё равно удаляются безвозвратно, как при успехе.
- Настройки уведомлений и видимость видов животных синхронизируются одним общим сетевым механизмом, независимым от локального сохранения в соответствующих экранах — правка, сделанная локально, доходит до сервера только со следующим полным sync-проходом, и то лишь для push (не для pull, который выполняется безусловно). Если сервер не возвращает список видимых видов, локальный выбор пользователя принудительно заменяется «все виды видимы».
