### 1. Добавить считывание QR-кода визуальной бирки при регистрации животного

**Раздел:** Регистрация животного → «Маркирование»

#### Описание

Добавить возможность считывания QR-кода визуальной бирки при добавлении средства маркирования в процессе регистрации животного.

#### Требуемое поведение

На странице «Маркирование» пользователь должен иметь возможность:

- открыть сканер QR-кода;
- считать номер визуальной бирки;
- автоматически заполнить поле номера средства маркирования;
- проверить считанное значение перед сохранением;
- при необходимости изменить номер вручную.

Ручной ввод номера должен оставаться доступным.

#### Критерии приёмки

- На странице «Маркирование» доступна кнопка или иконка сканирования QR-кода.
- После успешного сканирования номер автоматически подставляется в соответствующее поле.
- При ошибке или невозможности распознавания отображается понятное сообщение.
- Система выполняет действующие проверки формата и уникальности номера.
- Повторное сканирование не создаёт дубликат средства маркирования.

### 2. Отображать исходное отделение для животных с «чужой меткой»

**Раздел:** Инвентаризация → «Чужие метки»

#### Описание

Для животных, RFID-метка которых обнаружена при инвентаризации другого отделения или группы, необходимо отображать информацию о текущем месте их учёта.

#### Требуемое поведение

В разделе «Чужие метки» рядом с каждым животным необходимо показывать:

- наименование отделения, фермы или места содержания, в котором животное числится;
- номер средства маркирования и вид животного.

#### Критерии приёмки

- Для каждой «чужой метки» отображается исходное место учёта животного.
- Информация берётся из актуальных данных карточки животного.
- При отсутствии сведений отображается значение «Место содержания не указано».
- Наименование не обрезается без возможности просмотра полного значения.
- Термин «отделение» должен соответствовать фактической сущности системы: ферма, место содержания, площадка или подразделение.

### 3. Добавить переход из операции «Перемещение» в карточку животного и электронный паспорт

**Раздел:** Еженедельник → Перемещение

#### Описание

Реализовать открытие карточки животного из списка животных, включённых в зарегистрированное перемещение.

Аналогичный переход уже реализован в разделе регистрации животных и должен использоваться как образец поведения.

#### Требуемое поведение

При нажатии на строку животного в операции «Перемещение» пользователь должен получить возможность перейти:

- в карточку животного;
- в электронный паспорт животного.

После возврата пользователь должен оставаться на странице текущего перемещения.

#### Критерии приёмки

- Строка животного в списке является интерактивной.
- Открывается карточка выбранного, а не первого животного в списке.
- Из карточки доступен переход в электронный паспорт.
- После возврата сохраняются операция, позиция прокрутки и ранее открытый список.
- Переход работает как для одного животного, так и для группового перемещения.
- Права доступа проверяются по действующей роли пользователя.

### 4. Изменить отображение номера животного в реестре

**Раздел:** Реестр животных

#### Описание

Длинные номера средств маркирования занимают значительную часть карточки животного и ухудшают визуальное восприятие реестра. Необходимо привести отображение номера к единому компактному формату.

#### Рекомендуемое решение

В реестре животных отображать последние четыре цифры номера средства маркирования, используя тот же принцип, который применяется в календаре или других компактных списках.

Полный номер должен быть доступен:

- в карточке животного;
- в электронном паспорте;
- либо по нажатию на сокращённый номер.

#### Пример

Полный номер:

000635315416133

Отображение в реестре:

…6133

#### Критерии приёмки

- В реестре используется единый формат отображения номера.
- Пользователь понимает, что номер сокращён: перед четырьмя цифрами ставится многоточие.
- Полный номер доступен без перехода к редактированию данных.
- Поиск продолжает работать по полному номеру.
- Сортировка и фильтрация выполняются по исходному полному значению.
- Для коротких номеров сокращение не применяется.

### 5. Отображать дополнительное средство маркирования в карточке животного

**Раздел:** Карточка животного → Маркирование

#### Описание

В карточке животного необходимо отдельно отображать основное эмиссионное средство маркирования и дополнительные средства маркирования, которые не относятся к средствам, выданным или эмитированным в системе.

#### Требуемое поведение

В карточке животного необходимо отображать:

1. **Основное средство маркирования -** эмиссионное средство маркирования;
2. **Дополнительные средства маркирования -** электронные метки стороннего происхождения;

Основное и дополнительное средства маркирования не должны визуально смешиваться.

#### Критерии приёмки

- Основное средство маркирования выделено отдельно.
- Дополнительная «не наша» метка отображается в карточке животного.
- Для каждого средства понятно, является оно основным или дополнительным.
- Добавление дополнительного средства не заменяет основное.
- Удаление или деактивация дополнительной метки не нарушает историю основного номера.
- При наличии нескольких дополнительных средств отображается полный список.

### 6. Добавить сведения об организации в профиль пользователя

**Раздел:** Профиль пользователя

#### Описание

Добавить в профиль пользователя блок с информацией об организации, указанной при регистрации пользователя.

Сведения предоставляются только для просмотра, без возможности редактирования.

#### Отображаемые данные

Необходимо показывать только фактически сохранённые при регистрации сведения, например:

- наименование организации;
- ИНН или иной идентификатор, если он вводился;
- адрес;
- роль пользователя в организации.

Точный набор полей должен соответствовать данным, которые имеются в учётной записи.

#### Критерии приёмки

- В профиле отображается блок «Организация».
- Пользователь видит организацию, к которой прикреплена его учётная запись.
- Поля доступны только для чтения.
- Кнопки редактирования отсутствуют.
- Пустые поля не выводятся либо отображаются единообразно как «Не указано».
- Отображаемые сведения соответствуют данным, введённым при регистрации или назначенным администратором.

### 7. Скорректировать настройки RFID-считывателя

**Раздел:** Профиль → Подключение устройств → настройки RFID-считывателя

#### Описание

На странице настроек устройства необходимо скорректировать наименование параметра и дополнить описание доступных частотных диапазонов.

#### 7.1. Переименование параметра

Заменить наименование: **Мощность**

на: **Дальность считывания**

При необходимости техническое значение мощности можно оставить во внутренней модели, но пользователю должен отображаться понятный параметр дальности считывания.

#### 7.2. Отображение стран и регионов для частотного диапазона

В списке выбора частотного диапазона необходимо указывать страны или регуляторный регион, для которых предназначен соответствующий диапазон.

**Пример формата**

ETSI 866–868 МГц — Россия / Европа

FCC 902–928 МГц — США / соответствующие страны

Фактические страны и диапазоны необходимо заполнить на основании документации производителя устройства и требований к использованию радиочастот.

#### Критерии приёмки

- На странице отсутствует пользовательское название «Мощность».
- Используется наименование «Дальность считывания».
- Выбранное значение корректно передаётся устройству как уровень мощности.
- Для каждого частотного диапазона указан регион или перечень поддерживаемых стран.
- Значение по умолчанию соответствует региону эксплуатации приложения.
- Пользователь предупреждается, если выбирает диапазон, не предназначенный для установленного региона.
- Изменения сохраняются и применяются после повторного подключения устройства.

### 8. Исправить регистрацию фермы: обязательность названия и перекрытие кнопки клавиатурой

**Раздел:** Главная страница → «+» → Регистрация фермы

#### Описание

На первом шаге регистрации фермы выявлены две проблемы:

1. Пользователь может перейти на следующий экран, не указав название фермы.
2. При открытой клавиатуре кнопка перехода частично или полностью перекрывается, из-за чего невозможно продолжить регистрацию.

#### 8.1. Валидация наименования

Поле «Название» должно быть обязательным.

#### Требуемое поведение

- Переход на следующий шаг допускается только после ввода корректного названия.
- Значение, состоящее только из пробелов, считается незаполненным.
- При попытке продолжить без названия поле подсвечивается.
- Отображается сообщение:  
  **«Укажите название фермы»**.

#### 8.2. Работа с экранной клавиатурой

Интерфейс должен корректно адаптироваться при открытии клавиатуры.

Возможные способы реализации:

- экран прокручивается до активного поля и кнопки;
- кнопка перехода располагается над клавиатурой;
- после нажатия «Готово» клавиатура закрывается;
- нажатие вне поля закрывает клавиатуру.

#### Критерии приёмки

- Без заполнения поля «Название» перейти дальше невозможно.
- После ввода названия кнопка перехода становится доступной.
- Клавиатура не перекрывает поле и кнопку перехода.
- Экран корректно работает на устройствах с разными размерами дисплея.
- После возврата на предыдущий шаг введённое название сохраняется.
- Двойное нажатие на кнопку не создаёт несколько одинаковых ферм.
