# Добавить переход в карточку животного из дневных отчётов (перемещение/вакцинация/выбытие)

## Объём

Один общий виджет `EventReportBody`/`EventReportGroup`
(`lib/widgets/event_report/event_report_template.dart`) используется тремя
экранами:
- `MovementReportCubit` (`lib/pages/movement_report/`)
- `VaccinationReportCubit` (`lib/pages/vaccination_report/`)
- `DisposalReportCubit` (`lib/pages/disposal_report/`)

Все три отбрасывают `animalId` при построении `EventReportGroup` (остаётся
только номер бирки). Нужно:

1. Добавить `animalId` (или список пар `(animalId, number)`) в
   `EventReportGroup`/модель строки, прокинуть его из всех трёх cubit'ов.
2. Сделать строку животного в `_HighlightedNumber`/её обёртке (внутри
   `_KindAccordion`, `event_report_template.dart:104-210`) тапабельной:
   `context.pushNamed2(Routes.animalDetailsFromSearch, extra:
   AnimalCardExtra(animalId: ...))` — тот же вызов, что уже в
   `lib/pages/registration_day_report/presentation/widgets/registration_day_report_view.dart:54-58`.

Переход — один, в `AnimalCardPage`; отдельного экрана «электронный паспорт»
нет и не заводится. Проверки прав доступа не требуется.

Полное обоснование и CURRENT/TARGET — `UC-309`/`UC-310`/`UC-311` (текст
идентичен по сути, различаются только исходные cubit'ы/сущности).

## Критерии приёмки (definition of done)

- [ ] Строка животного в отчёте по перемещению тапабельна, открывает карточку именно этого животного.
- [ ] То же — в отчёте по вакцинации.
- [ ] То же — в отчёте по выбытию.
- [ ] Открывается карточка выбранного, а не первого животного в списке/группе — для всех трёх отчётов.
- [ ] После возврата пользователь остаётся на той же странице отчёта, с той же развёрнутой группой и позицией прокрутки (обеспечивается самим `push`, без дополнительного кода для сохранения состояния).
- [ ] Работает и для одного животного, и для группового перемещения/группы вакцинации/выбытия.
- [ ] Проверки прав доступа нет — не добавляется (критерий тикета снят как ошибочный).
- [ ] Тап на заголовке группы (`_KindAccordion`) по-прежнему только сворачивает/разворачивает — не конфликтует с тапом на строке животного.

## Реализационные заметки

- Менять `event_report_template.dart` один раз — не форкать его под три отдельных набора виджетов ради этой задачи.
- `Routes.animalDetailsFromSearch` + `AnimalCardExtra(animalId: ...)` — не изобретать новый route/extra-класс, эталон уже есть.
- Тестовые группы во всех трёх cubit-тестах именуются по старым UC (`UC-149`/`UC-109`/`UC-163`) — при реализации переименовать на `UC-309`/`UC-310`/`UC-311` соответственно (правило самопривязки теста к спеке).
- Не добавлять код проверки прав/ролей — явно не входит в объём (см. `design`/BT-20).

(`AnimalCardExtra`, `Routes.animalDetailsFromSearch`, `pushNamed2`) уже
существует и используется идентичным образом в соседнем отчёте регистрации.
