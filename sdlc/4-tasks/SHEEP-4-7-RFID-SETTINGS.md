# Настройки RFID-считывателя: «Дальность считывания», страны для диапазонов, исправление применения на устройство

## Объём

### 7.1 — переименование лейбла

`select_power_slider.dart:85`) — заменить значение «Мощность» на «Дальность

   уже передаётся корректно, не трогать).
2. `lib/scanner/scan_grp_ble.dart` `connect()` — добавить чтение сохранённых

### Явно не в объёме

- Предупреждение «диапазон не для вашего региона» — снято постановщиком, отдельная задача с обсуждением дизайна/формулировки.
- Чистка мёртвого кода (`ScannerService.setTerminalRegion()`,
  `tryApplyGatesBleRadioSettings()` — без вызывающих мест в `lib/`) —
  упомянуть как находку, не обязательное требование этой задачи.
- TCD-терминал и SMART-GATE BLE — уже работают корректно, не трогать.

## Критерии приёмки (definition of done)

- [ ] Лейбл «Мощность» нигде не отображается — везде «Дальность считывания».
- [ ] Для каждого из 10 значений `DeviceRegion` в выпадающем списке указана страна/регион.
- [ ] SMART-GATE TCP и RFID-04 TCP корректно передают на устройство любой выбранный регион (не только 0–3), включая дефолтный ETSI.
- [ ] RFID-03 handheld реально получает мощность/регион на устройство при подключении.
- [ ] TCD-терминал и SMART-GATE BLE — поведение не меняется.
- [ ] A7/UHF-стик — без изменений.
- [ ] Предупреждение о регионе — не построено (сознательно, не забыто).

## Реализационные заметки

- 7.1/7.2 — чистые правки текста/локализации, без изменения моделей/логики сохранения.
- Баг-фиксы 1–2 — точечные правки в native-facing коде (`scan_tcp.dart`/`scan_grp_tcp.dart`/`scan_grp_ble.dart`); тестировать на реальном железе каждого из трёх типов устройств перед мержем — статический анализ/юнит-тест региона-свитча не гарантирует, что аппаратный код читалки соответствует индексу `DeviceRegion` 1:1 (см. открытый вопрос в `UC-314`).
- Не трогать мощность в `scan_tcp.dart`/`scan_grp_tcp.dart` — она уже передаётся корректно, баг только в регионе.

## Зависимости

Баг-фиксы требуют доступа к реальным устройствам (SMART-GATE TCP, RFID-04, RFID-03) для проверки — не блокирующая, но необходимая для приёмки зависимость.
