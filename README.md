# SDLC-платформа REGAGRO Livestock

«Мозг процесса» разработки, вынесенный из репозитория приложения в отдельный
репозиторий (позже — на сервер). Содержит:

- **`sdlc/`** — дерево SDLC (PRD, бизнес-задачи, спеки, задачи, результаты …),
  каноничная копия. Живёт по строгому «закону» (`sdlc/AGENTS.md`): артефакты
  замораживаются при записи, «изменить» = выпустить новый id и **похоронить**
  старый, in-place правится только PRD.
- **`mcp/`** — Python MCP-сервер (`sdlc-mcp`), которым управляет Claude Code. Он
  предоставляет инструменты над `sdlc/`, **сторожит закон** и **аудирует каждое
  изменение** (кто/что/когда), плюс ведёт транскрипт сессии. Внешние действия
  (PR, сборка APK, доставка в Telegram) — интерфейсы с фейками, реальные вызовы
  включаются добавлением ключей.
- **`docs/`** — установка, архитектура, TDD, аудит.

Приложение остаётся в `AGROSERVIS-MOBILE/agro_system` — MCP делает туда PR и
собирает APK; сюда его код не копируется.

## Модель

MCP — это **слой инструментов**, а не агент. «Получает запрос, задаёт вопросы,
ведёт по SDLC» делает Claude Code, вызывая инструменты сервера. Сервер даёт
структурированные, аудируемые операции и промпты-воркфлоу (`run_pass`,
`new_feature`, `tdd_task`).

## Быстрый старт

```bash
cd mcp
uv sync                      # поставить зависимости (Python 3.11)
uv run pytest                # прогнать тесты
uv run python scripts/smoke.py   # end-to-end смоук по stdio
uv run sdlc-audit history    # история изменений
```

Регистрация в Claude Code, ключи для PR/Telegram/APK и перенос на сервер —
в [`docs/SETUP.md`](docs/SETUP.md). Архитектура — [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

> На этой машине `~/.local` принадлежит `root`, поэтому рядом лежит
> машинно-специфичный `mcp/uv.toml` (в `.gitignore`), указывающий uv на writable
> кэш и системный Python 3.11 (Homebrew). На нормальной машине он не нужен.
