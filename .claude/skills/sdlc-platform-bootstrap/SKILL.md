# Bootstrap SDLC-платформы для нового проекта

Разворачивает такую же платформу, как эта: Python MCP-сервер, который сторожит
«закон» SDLC (freeze / entomb / PRD-in-place), аудирует каждое изменение и ведёт
транскрипт сессии, плюс интерфейсы внешних действий (PR / APK / Telegram) с
фейками. Мозг — внешний Claude (коннектор claude.ai или локальный Claude Code);
MCP — общий слой инструментов (stdio локально, SSE+токен за nginx/TLS на сервере).

## Что переиспользуется как есть (project-agnostic)

Весь движок `mcp/` универсален — ничего проектного в коде нет:

- `law/` — закон SDLC (id, шаблоны, freeze/entomb, PRD, validate);
- `audit/`, `transcript/` — журналы;
- `integrations/` — Protocol'ы + фейки + реальные (git/gh, flutter, Telegram);
- `service.py`, `server.py`, `config.py`, тесты.

## Что задаётся под проект (не код, а конфиг)

- `SDLC_ROOT` — дерево `sdlc/` этого проекта;
- `APP_REPO_PATH` — репозиторий приложения (для PR/сборки);
- `mcp/.env` — секреты (Telegram, gh);
- команда сборки в `integrations/apk_build.py` — если приложение **не** Flutter,
  замени `flutter build apk` на сборку своего стека (это единственное место с
  предположением про стек).

## Шаги

1. **Запусти скрипт** из этого скила (копирует движок, заводит дерево `sdlc/`,
   docs и git):
   ```bash
   bash .claude/skills/sdlc-platform-bootstrap/bootstrap.sh \
        <путь-к-новой-платформе> [путь-к-существующему-sdlc]
   ```
   - без второго аргумента создаётся минимальный scaffold `sdlc/` (10 стадий +
     PRD-заглушка), с которым инструменты работают сразу;
   - со вторым аргументом — копируется существующее дерево `sdlc/` проекта.
   Если у команды есть отдельный scaffold стадий с `AGENTS.md`/`README.md`
   (методология пайплайна) — прогони его поверх, чтобы получить полные конвенции.

2. **Поставь и проверь**:
   ```bash
   cd <новая-платформа>/mcp
   uv sync && uv run pytest && uv run python scripts/smoke.py
   ```
   На машине с root-owned `~/.local` создай `mcp/uv.toml` как в исходной платформе
   (см. её `docs/SETUP.md`, раздел 1); на нормальной машине он не нужен.

3. **Зарегистрируй MCP** в Claude Code и **настрой ключи** — по `docs/SETUP.md`
   новой платформы (файлы скопированы шагом 1): разделы 3 (регистрация) и 4
   (GitHub / Telegram / APK).

4. **Создай git-репозиторий** платформы (`docs/SETUP.md`, раздел 5) — приложение
   остаётся в своём репозитории, MCP делает туда PR.

5. **Работай через промпты** сервера: `run_pass` (прогон цикла SDLC),
   `new_feature` (запрос → бизнес-задача → спеки → задача), `tdd_task` (red→green
   для кода). Историю смотри `uv run sdlc-audit history`.

## Правило TDD (переносится в новый проект)

Любой мутирующий метод сервиса готов только с тестом, что он (а) соблюдает закон и
(б) оставляет строку в аудите. Задачи по коду приложения — red→green→refactor с
обязательным прогоном тестов проекта. Подробно — `docs/TDD.md`.
