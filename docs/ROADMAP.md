# Roadmap / идеи по доработке платформы

Отложенные улучшения самого MCP-движка (не целевого проекта). Каждый пункт —
отдельная мысль; объём указан грубо. Разработка — по TDD, как и всё остальное.

## M5 — Мультипроектность (сейчас движок одно-проектный)

**Текущее ограничение (по состоянию на 2026-07-28).** MCP наведён на ОДИН проект
через `mcp/.env`: `SDLC_ROOT`, `APP_REPO_PATH`, `APP_BASE_BRANCH`, `APP_TEST_CMD`.
Все ~30 инструментов работают с этим одним клоном. Чтобы сменить проект — правишь
`.env` и `systemctl restart sdlc-mcp`; движок целиком переезжает на новый проект,
старый перестаёт обслуживаться. Одновременно два проекта одним коннектором нельзя.

**Ключевая мысль.** Склонировать ещё один репозиторий на сервер — это только
«что» (папка с файлами на диске). MCP её не тронет, пока не задано «куда
смотреть». Сейчас «куда смотреть» = одно значение в `.env`. Мультипроектность =
добавить выбор «куда смотреть» на лету.

**Что нужно.**
1. **Реестр проектов** — файл `mcp/projects.toml` (gitignored, специфичен для
   сервера): `name → { sdlc_root, app_repo, base_branch, test_cmd }`. Добавить
   проект = дописать блок + склонировать репо (+ deploy key). Без правки кода и
   без редеплоя.
2. **Механизм выбора** (развилка):
   - **A. Параметр `project` у инструментов.** Claude берёт имя из слов
     пользователя («…в **lifestocks**» → `project=lifestocks`). Per-call →
     **безопасно на общем сервере**: нет глобального «текущего проекта», который
     другой работник мог бы переключить под тобой. Соответствует «сказал имя — он
     выбрал».
   - **B. Проект по URL коннектора** (`token → project`), per-connection. Проще в
     реализации, но проект выбираешь ссылкой, а не словом.

**Объём.** Рефактор: «проект» должен протечь через `SdlcService` и все инструменты
(сейчас жёстко `self.cfg.sdlc_root` / `self.cfg.app_repo`). Плюс загрузка реестра
в `config.py`. Дефолт-проект оставить, чтобы одно-проектный сценарий не усложнялся.

## Прочие отложенные мысли

- **Аудит на общем сервере — личность автора.** `actor_human` берётся из
  `ACTOR_HUMAN` / git user — на общем коннекторе все правки числятся за одним
  «человеком». Для мультипользовательского аудита — привязать личность к
  подключению (например `token → user` в реестре токенов).
- **Telegram через прокси.** Доставку APK перенесли в GitHub Release, т.к. сервер
  (РФ) не достаёт `api.telegram.org`, плюс бот-лимит 50 МБ. Если появится
  прокси/relay, доступный серверу, — вернуть Telegram каналом (добавить прокси в
  `RealTelegramSender`) и уменьшать APK (release + split-per-abi) под 50 МБ.
- **Release-подпись APK.** `mode="release"` требует keystore
  (`android/key.properties`). Добавить опциональную конфигурацию keystore на
  сервере, чтобы собирать подписанный release, а не только debug.
- **Упаковка scaffold-шаблонов.** `mcp/src/sdlc_mcp/scaffold_templates/` работает
  при запуске из исходников (на сервере так и есть). Для pip/wheel-установки —
  объявить их как package-data в `pyproject.toml`.
- **Артефакты сборки на диске.** Каждая сборка оставляет `build/` в клоне (сотни
  МБ). Продумать очистку/ротацию, если сборок будет много.
